# dsh-web-chat 0.6.0 缺陷修复说明

本轮在 0.6.0 基础上修复八项缺陷，版本号与导入格式不变。全部测试使用模拟服务、虚构密钥与合成数据，不连接真实账号。新增回归测试均在 `test/`，构建产物在项目目录内。

## 逐项修复与验证

### ① 更换服务地址时隔离旧密钥
- **修了什么**：凭据绑定到规范化来源（协议+主机+端口，`serviceOrigin`）。新增统一校验 `resolveBoundKey`，回复、连接诊断、生图、生图诊断共用。保存时：填新密钥→绑定当前来源；同来源编辑名称/模型/路径→保留原密钥（旧配置惰性迁移）；换来源且留空密钥→清除旧密钥、标记未配置。
- **验证输入**：两个本机回环端口模拟两个来源，记录上游实际收到的密钥/模型（`test/credentials.mjs`）。
- **实际结果**：14/14 通过。编辑名称/模型后原密钥仍可用；换域名留空密钥后新域名收不到旧密钥（回复/诊断/生图均拒绝）；新来源配新密钥后正常。
- **仍需桌面验收**：设置 UI 中改地址后的提示文案与重新配钥流程。

### ② 附件跟随实际选中的模型
- **修了什么**：添加附件改为本地优先（存 IndexedDB 原件+预览，不立即上传 DeepSeek）。发送时按当前模型协议准备：DeepSeek 走 Files API file_id；OpenAI/Anthropic/Spark 用自身 base64 格式（`buildAttachmentBlocks`）。发送前同步能力校验（`attachmentSupportError`），不支持的具体提示并保留草稿。历史附件切模型后从本地原件重新准备。适配器不再把 DeepSeek file_id 泄漏给第三方；Spark 转发 base64 图片。
- **验证输入**：纯函数+协议转换内存测试（`test/attachments.mjs`）。
- **实际结果**：12/12 通过。第三方图片转 base64/image_url；OpenAI 文档拒绝；非视觉模型图片拒绝；第三方请求不含 DeepSeek file_id。
- **仍需桌面验收**：第三方模型实际发图、仅附件发送、添加附件后切模型的端到端 UI 流程（IndexedDB/FileReader 需浏览器）。

### ③ 历史备份完整恢复生成图片
- **修了什么**：导出把助手生成图以 FILE 片段保存原件引用，另写 `dswc_generated.json` 元数据侧车（prompt/provider/model/createdAt/parentId）。导入读取侧车后还原聊天内生成图卡片，写盘成功后恢复图库（含编辑派生 parentId）。兼容旧备份与官方归档（无侧车时不还原生成图但不报错）。损坏/失败时暂存清理，现有会话与图库不受影响。
- **验证输入**：含生成图+编辑派生图的会话，导出 ZIP 再导入（`test/history-images.mjs`，真实 zipWriter/zipReader/schema）。
- **实际结果**：13/13 通过。卡片/提示词/模型/派生关系/图片引用全部还原；无侧车兼容；非 ZIP 与截断归档失败路径正确。
- **仍需桌面验收**：图库 IndexedDB 恢复、大图查看器、派生关系在 UI 的呈现。

### ④ 每条回复下方的用量统计
- **修了什么**：新增 `createUsageAccumulator`，区分单次上游请求用量与整条回复累计用量。工具往返各请求计入，同请求累计用量事件取最终值。统一输入/输出/缓存读/缓存写口径（Anthropic 适配器补 cache_creation）。缓存缺失→命中率 null（—），明确零命中→0%。TPS 按各轮首→末 token 有效生成时间，排除工具/生图/联网等待。
- **验证输入**：内存测试（`test/usage.mjs`）。
- **实际结果**：8/8 通过。两轮输出 8+12→显示 20；缓存未报告→—；明确零命中→0%；长时间工具等待不计入 TPS。
- **仍需桌面验收**：真实流式回复下统计条渲染。

### ⑤ 自动化选择 DeepSeek 官方模型后报错
- **修了什么**：抽出 `automationOp`，显式 `deepseek-official` 或未指定模型走普通 `messages` 路径，自定义/Harness/Spark 走 `model-reply`。
- **验证输入**：路由判定内存测试（`test/automation.mjs`）。
- **实际结果**：默认/官方/自定义/Harness/Spark 五种路由全部正确（11/11 含）。
- **仍需桌面验收**：自动化实际触发三种模型的真实请求。

### ⑥ 自动化取消和结果投递
- **修了什么**：Host 每个运行中任务持独立 AbortController，删除时精确取消；写收件箱前校验任务仍存在且运行 ID 有效，并按运行 ID 去重。前端 `deliverAssistantText` 异步加载未打开会话、写盘成功后才确认收件；`deliverInbox` 按运行 ID 持久化去重，写盘失败保留收件箱可重试。
- **验证输入**：内存竞态测试（`test/automation.mjs`，可控 generate 与时序）。
- **实际结果**：运行中删除、删除后上游仍返回→不投递；正常完成投递一次；运行 ID 唯一；失败标记 error（11/11 含）。
- **仍需桌面验收**：目标会话未打开投递、写盘失败重试、重复投递在真实 IndexedDB 下的表现。

### ⑦ 自定义生图执行并记录实际模型
- **修了什么**：所选模型传到后端，自定义服务校验模型属于该服务且支持当前操作（文生图/参考图编辑），不支持的组合直接拒绝；默认模型仅未指定时用。响应头 `x-image-model` 返回实际请求模型，前端图库据此记录。
- **验证输入**：两个模拟模型验证文生图与参考图编辑（`test/credentials.mjs`）。
- **实际结果**：控件所选值=上游请求模型=图库记录；编辑模型正确传递；不支持组合拒绝（14/14 含）。
- **仍需桌面验收**：真实图像服务下两个模型的实际出图。

### ⑧ 打包可在另一套本地环境重建
- **修了什么**：`pack.mjs` 移除 Windows 用户目录硬编码；pnpm/python 按「显式环境变量（DSWC_PNPM_PATH/DSWC_PYTHON_PATH）→当前 Node 运行时同级依赖→PATH」发现。新增内置 Node tar 写入器（fflate）作为 python 不可用时的兜底（`--node-tar` 可强制）。正式/离线包分别校验清单、入口、面板资源与离线配置。
- **验证输入**：实际打包正式+离线包，并强制 node-tar 兜底打包后用 python tarfile 复核。
- **实际结果**：两种写入器均产出有效 tgz（package/ 前缀、清单/入口/面板/桌宠齐全）；正式包 lib 哈希与通过测试的 Host 构建一致；离线包含模拟服务配置。
- **仍需验收**：在另一套无 bundled python 的环境用 `--node-tar` 完整重建。

## 运行时反馈修复（安装后实测）

后端用真实凭据实测均正常（混元生图 13.5s/编辑 18.4s、动态模型 live 18 个、讯飞流式+工具往返），据此定位并修复三个前端/调度问题：

### A. 聊天里让画图只回文字、不出图
- **根因**：`generate_image` 工具已正确传给模型（Spark 工具格式 parameters 正确），但第三方模型未主动调用；且生图失败时错误只藏在生图对话框，聊天里看不到原因。
- **修复**：已配置图像服务时在系统提示加入强引导（要求绘画类请求必须调用 `generate_image`，禁止仅文字描述）；生图失败时在聊天时间线插入可见的错误步骤（含真实原因）。
- **仍需桌面验收**：Spark/自定义模型实际说"画一张…"是否触发出图（模型行为依赖提示引导）。

### B. 图像服务商不能动态获取模型
- **根因**：预设动态拉取后端正常；自定义图像服务此前只显示手填的生图/编辑模型，未做动态拉取。
- **修复**：`listImageModels` 支持自定义服务——从端点来源推导 `/v1/models`，按 image 关键词过滤，失败回退配置模型；前端 ImageStudio 统一走动态拉取。
- **验证**：`test/image-models.mjs` 5/5（自定义 live 过滤、预设无 Key fallback、未知 provider fallback）。

### C. 模型回答卡顿
- **根因**：思考卡片流式时默认展开，实时重解析整段思考 Markdown（Spark reasoning_content 很长），每帧重渲染拖慢 UI。
- **修复**：思考卡片默认折叠，流式只渲染轻量"内心戏"标题，点击展开或结束后才渲染全文（ChatGPT 式），大幅降低流式渲染开销。
- **仍需桌面验收**：长思考回答的流畅度主观感受。
